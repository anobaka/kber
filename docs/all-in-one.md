# 企业级知识库管理工具 - 总体执行文档

## 1. 项目目标

构建一个企业级知识库管理系统（KBER），通过飞书机器人作为统一交互入口，自动采集群聊消息和代码仓库内容，经 LLM 归纳总结后存入向量数据库，提供智能知识检索与问答能力。

## 2. 系统架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        飞书机器人 (入口)                         │

└──────────┬──────────────────┬──────────────────┬────────────────┘
           │                  │                  │
    ┌──────▼──────┐   ┌──────▼──────┐   ┌──────▼──────┐
    │  命令处理器   │   │  消息采集器  │   │  RAG 查询   │
    │ 绑定/解绑    │   │ 实时+补偿    │   │ 检索+生成   │
    └──────┬──────┘   └──────┬──────┘   └──────┬──────┘
           │                  │                  │
    ┌──────▼──────────────────▼──────┐   ┌──────▼──────┐
    │          MySQL                 │   │   Milvus    │
    │  业务数据 / 绑定关系 / 消息存储  │   │  向量检索    │
    └──────┬──────────────────┬──────┘   └──────▲──────┘

    ┌──────▼──────┐   ┌──────▼──────┐           │
    │ 代码分析引擎 │   │ 消息归纳引擎 │───────────┘
    │ AST+LLM     │   │ LLM 总结    │
    └─────────────┘   └─────────────┘
```

## 3. 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 交互入口 | 飞书开放平台 | 自建应用，长连接模式 |
| 后端服务 | Python | 主服务 |
| 关系型数据库 | MySQL | 业务数据存储 |
| 向量数据库 | Milvus | 知识向量存储与检索 |

| 缓存/锁 | Redis（可选） | 分布式锁，防任务重入 |

## 4. 核心模块

### 4.1 飞书机器人交互模块

详见 → [channel.md](channel.md)

**职责**：
- 接收并解析用户命令（绑定/解绑知识库、绑定/解绑代码库、添加知识、立即总结、查询知识库、添加/移除管理员、恢复构建、清空上下文、帮助、自由提问）
- 实时采集群聊消息
- 历史消息补偿拉取
- Prompt 安全防护
- 消息回复（飞书卡片格式）

### 4.2 聊天记录分析模块

详见 → [analyze-messages.md](analyze-messages.md)

**职责**：
- 每 5 分钟定时归纳新消息为知识
- LLM 驱动的增量归纳（非全量重建）
- 知识去膨胀（合并相似、老化清理、容量控制）
- 手动添加知识的即时处理
- RAG 检索与回答生成

### 4.3 代码库分析模块

详见 → [analyze-repo.md](analyze-repo.md)

**职责**：
- Git 仓库克隆与增量拉取
- 文件过滤与敏感信息脱敏
- Tree-sitter AST 解析，按语义单元切分
- LLM 生成代码知识描述
- Diff-based 增量更新 Milvus
- 代码知识去膨胀（文件级替换、孤儿清理）

## 5. 数据流

### 5.1 消息 → 知识 流程

```
用户在群中发消息
  → 飞书长连接推送事件
  → 判断该群是否绑定知识库
  → 是：保存消息到 MySQL (chat_message, processed=false)
  → 每 5 分钟定时任务：
    → 以 kb_id 为 key 并发执行
    → 加载未处理消息，LLM 话题分组
    → 判定每个话题组状态（已结论/已沉寂/进行中）
    → 仅对已结论和已沉寂的话题组执行 LLM 归纳（提取最终结论）
    → 更新 Milvus（新增/更新/删除向量，附带确定性标记）
    → 标记已归纳消息 processed=true，进行中的消息保留到下轮
```

### 5.2 代码 → 知识 流程

```
用户绑定代码库 / 定时检查代码更新
  → git clone / git fetch + diff
  → 文件过滤 + 敏感信息脱敏
  → Tree-sitter AST 解析 → 代码块列表
  → 生成 Repo Map
  → LLM 为每个代码块生成知识描述
  → Embedding → 存入 Milvus
  → 增量更新：新增/修改/删除对应知识
  → 绑定时立即触发全量分析，实时向群通报进度
```

### 5.3 提问 → 回答 流程

```
用户 @机器人 提问
  → Prompt 安全检查
  → 查询该群绑定的所有知识库（含代码知识库）
  → 问题 Embedding
  → Milvus 多 Collection 并行检索 (topK=10/collection)
  → 合并排序取 top 15
  → 加载多轮对话上下文（最近 5 轮 Q&A，清空上下文命令可跳过）
  → 构建 RAG Prompt (系统指令 + 参考资料 + 对话历史 + 用户问题)
  → LLM 生成回答
  → 记录本次 Q&A 到对话历史
  → 飞书 Interactive Card 格式回复（支持 Markdown 渲染）
```

## 6. 定时任务汇总

| 任务 | 频率 | 说明 |
|------|------|------|
| 消息归纳 | 每 5 分钟 | 以 kb_id 为 key 并发，归纳新消息为知识 |
| 历史消息补偿 | 每 30 分钟 | 拉取最近 1 小时消息，按 message_id 去重 |
| 代码库更新检查 | 每 30 分钟 | git fetch + diff，增量更新代码知识 |
| 知识去膨胀 | 随归纳任务执行 | 合并相似知识、清理冷知识 |
| 代码库全量重建 | 每周一次（可选） | 修复增量遗漏，清理孤儿知识 |

## 8. 知识管理核心原则

### 8.1 增量归纳，非全量重建

每次归纳只处理新数据，与已有知识做对比合并，避免重复计算和 API 浪费。

### 8.2 话题分组与讨论沉淀

群聊消息不逐条归纳，而是先按话题分组，再判定讨论状态（已结论/已沉寂/进行中）。只有"已结论"和"已沉寂"的讨论才提取知识，进行中的讨论暂不处理，避免归纳中间态、被推翻的观点。知识条目附带确定性标记（确定/有分歧/待确认），影响 RAG 检索时的排序权重。详见 analyze-messages.md 第 4.2 节。

### 8.3 知识去膨胀

所有知识库（聊天/代码/手动）均遵循：

- **合并相似**：余弦相似度 > 0.92 的条目合并
- **老化清理**：90 天未引用且未更新的冷知识清理
- **容量控制**：每个知识库软上限 10000 条，硬上限 15000 条
- **代码库特有**：文件级替换、孤儿知识清理

### 8.4 多源知识融合

在 RAG 检索时，聊天知识、代码知识、手动知识统一检索，通过 `source` 字段区分来源，回答时标注出处。

## 9. 安全策略

- **Prompt 注入防护**：输入预处理 + Prompt 结构隔离 + 输出审查（详见 channel.md 第4节）
- **代码敏感信息脱敏**：发送给 LLM 前检测并替换密钥/密码（详见 analyze-repo.md 第3.3节）
- **权限控制**：机器人仅响应 @自身 的消息（非 @其他人），管理员命令需 `admin_user` 表授权，支持动态添加/移除管理员
- **审计日志**：安全拦截、归纳任务、LLM 调用均有日志记录
